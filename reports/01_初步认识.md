## 入口与层次

Application：`com.sqwan.msdk.SQApplication`，继承 `com.sy37.huawei.HmsApplication`。

Launcher：`com.game.sdk.GameSdkActivity`。继承链最终到 `com.game.core.GameActivity` / `org.cocos2dx.lib.Cocos2dxActivity`。

Manifest 中 `android.app.lib_name=cocos2dlua`；`Cocos2dxActivity.onLoadNativeLibraries()` 从 metadata 读取库名并 `System.loadLibrary()`。具体方法以当前 Java 导出为准。

可确认的分层：

```text
Android Application / Launcher
  ├─ 三七／华为渠道、登录、支付、推送、实名等 SDK
  ├─ Java <-> JNI / Lua bridge
  └─ libcocos2dlua.so
      ├─ Cocos2d-x / Lua 5.1 相关引擎代码
      ├─ AppDelegate / CCGameMain / ResourcesDecode
      ├─ bootstrap 资源 -> main.lua
      └─ FairGuard native 与资源前置处理
```

Java 中可见 `sdkBackInit`、`sdkBackSwitchAccount` 等回调，以及 `GameHelper.nativeCallLuaFunc()`，说明关键客户端逻辑不能只看 Java。`libnative-lib.so` 另有 `NativeUtils` JNI 封装及 AES 相关导出，不能与游戏核心 Cocos 库混为一谈。

APK 还包含 `assets/sq_plugin_3.7.8.6.2_2023_04_14_12_21_14.apk` 渠道插件。本轮 6 个 DEX 的统计不包含嵌套 APK 内代码。

## 是否加壳

**可以确认 native 层存在保护／加壳，且 FairGuard 参与资源解密链路。暂未发现整个 Java 层被传统 DEX 替身壳覆盖的证据。** 不对具体壳版本或全部保护功能作无证据归类。

| 证据 | 观察 | 含义 |
|---|---|---|
| Manifest + Java | 入口类和大量 SDK 代码直接可读 | Java 不是仅剩很小的加载器；不等于全部 Java 未混淆 |
| DEX 校验 | 6 个 DEX 均有效，共 11,955 个 class definitions | DEX 是可解析的实质代码 |
| 主引擎 ELF | `.text` 为 16 字节，地址 `0x190`，但 SO 大小约 16 MB | 节表无法代表真实代码布局 |
| 两个受保护 SO | 相似的 1,026 项壳侧 dynsym，含乱码、空名、超出正常映射的地址 | 符号元数据被保护，普通反编译器会受干扰 |
| 主引擎依赖 | `DT_NEEDED: libFairGuard.so` | 引擎直接关联 FairGuard |
| 运行时 | 主引擎与 FairGuard 主映射为 `rwxp`，代码／字符串可读 | 运行后存在可采集的解密内容；RWX 单独不是充分证据 |
| 解密入口 | `cocos+0x4c3fc8` 跳到匿名页，再到 `cocos+0xf739ec` | 存在运行时函数跳板 |
| 间接调用指针 | 前置函数落在 `FairGuard+0x341660` | 直接证实 FairGuard 处理资源密文 |

证据：`evidence/cocos.program_headers.txt`、两个 `*.elf.json`、`runtime_maps.txt`、`xxtea_hook.asm.txt`、`resource_preprocess.json`。

## 资源与 Lua

`assets/res/` 共 18,566 个条目，其中 18,549 个以 ASCII `ec9336077f73f54c` 开头，后续不是明文 PNG／Lua。哈希文件名本身不能证明加密；统一签名、解码实现与实际失败验证共同表明存在资源保护。

发现一个明文 Lua 格式索引：

`assets/res/3/6/296c64f9f32f76c4190b5b35ac73828f`

大小 1,830,814 字节，可解析出 13,071 条映射：10,924 条 PNG、1,048 条 JPG、1,099 条 FMOD bank。索引含活动、美术和语言资源路径，**不是 13,071 个已解密资源，也不是 Lua 业务源码**。没有在这个索引中找到 `.lua` / `.luac` 项。

运行时主引擎中发现 `main.lua`、`.luac`、Lua 5.1 搜索路径，以及启动资源：

`res/4/8/obk364w4z0k0oj248804e895vf968526wa845824b`

该资源在 APK 内长 2,096,668 字节，仍带上述保护签名。尚未确认解密结果是 Lua 文本、Lua 字节码或另一种封装；不能据此宣称 Lua 已恢复。

## 能否逆向所有逻辑

| 范围 | 当前状态与预期 |
|---|---|
| Android 入口、渠道桥接和多数 SDK | 已可阅读；JADX 有 26 个错误，必要时转 smali |
| Cocos 引擎／native 客户端代码 | 已取得可分析内存片段，可继续定位函数；仍存在壳侧跳板和被清理的元数据 |
| Lua 客户端逻辑 | 已定位装载与解密链；尚未获得加密业务脚本明文，无法给出覆盖率 |
| APK 内资源 | 获得明文索引与签名／密钥状态；尚未完成受保护资源批量恢复 |
| 热更新内容 | APK 未必包含当前运行版本的全部脚本与资源，需要单独核对 |
| 服务端战斗判定、发奖、经济校验等 | 若只在服务端实现，APK 无法提供其源码；本轮未探测服务器 |
| 原项目源码／注释／命名 | 编译或剥离后信息通常不可完整逆转 |

因此答案是：**能进一步还原大量客户端行为，但不能保证逆向“所有逻辑”，尤其无法从 APK 还原仅存在于服务器的实现。**
