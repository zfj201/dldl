# 脱壳方案、实际过程与结果

> 阶段更新：已恢复可读 Lua 并完成签到离线原型，详见 [06 资源解密记录](06_资源解密与业务恢复.md) 与 [07 模块实现记录](07_模块定位与签到原型.md)。下文保留该阶段的判断／计划，不代表最新完成状态。

## 目标与工具选择

本轮目标是建立样本认识，判断壳所在层，并尝试取得可分析代码。读取并采用了本机 `apk-reverse`、`ida-reverse`、`reverse-engineering` 技能。

本机实测工具：JADX 1.5.6、Apktool 3.0.3、ADB 37.0.1、Java 17、Python 3.9、pyelftools、Apple LLVM 21.0.0。

技能中部分脚本是 Windows PowerShell 版本。本机未在 PATH 检出 pwsh、IDA／idalib、radare2、Frida；`/Applications` 也未发现 IDA。`ida-reverse/scripts/start.ps1` 硬编码 Windows 路径，因此没有执行它或声称完成 IDA 分析。采用本机 LLVM + ELF 解析 + ADB 只读采集继续工作。JADX／Apktool 用等价原生命令落盘。

## 实际执行记录

### 1. 固定原始样本与静态导出：成功

读取下载目录 APK，记录 SHA-256 与 ZIP 条目，提取 DEX 和 SO；原 APK 保持不变。

```sh
python3 scripts/triage.py '/Users/zfj/Downloads/斗罗大陆：武魂觉醒.apk'
jadx -j 4 --no-res -d jadx extracted/classes*.dex
apktool d --no-assets -p extracted/framework -o apktool '/Users/zfj/Downloads/斗罗大陆：武魂觉醒.apk'
```

JADX exit 3，日志报告 26 个错误，但成功导出 6,898 个 Java 文件。Apktool exit 0，导出 11,955 个 smali 文件。Java 文件数与 DEX 类数不同，不能据此推导丢失同等数量的类，因为内部类等可能合并输出。

六个 DEX 的 header 长度、SHA-1、Adler32 均验证通过。主 Activity、Application 与 JNI 桥接可读，因此没有先盲目修改 smali。

### 2. 静态识别 native 保护：成功

用 pyelftools 读取 SO 的节表、符号、导入，用 LLVM 输出 program headers。主引擎的 `.text` 仅 16 字节、dynsym 异常、真实可执行映射远大于节表描述；FairGuard 库也出现相似布局。

判定：存在 native 保护。不是仅因为文件名含 `FairGuard` 就直接下结论。

资源头统计表明：18,549 个 `assets/res/` 文件具有相同 16 字节签名。保留头部样本清单，没有立即把这些文件当作原始 Lua。

### 3. 检查可用设备与样本一致性：成功

首次 sandbox 内 ADB 因本地监听权限失败；使用平台批准的提权执行重新查询成功。

- 设备：`23054RA19C`，Android 15，`arm64-v8a`。
- 已有 `su`，只读 `su -c id` 返回 uid 0。
- 游戏已安装并正在运行，采集时 PID 为 12854。
- 对已安装 `base.apk` 计算 SHA-256，与下载样本完全相同。
- 设备有 `/data/local/tmp/frida-server` 文件，但本轮没有启动它或注入 Frida。

证据：`logs/device_environment.txt`、`logs/device_root_and_sample.txt`。同 APK 哈希不保证下载的热更新内容完全相同，本轮未枚举热更新目录。

### 4. 读取两个 native 模块：成功，属于部分脱壳

从 `/proc/12854/maps` 确认模块范围，通过 root 下的 `dd if=/proc/12854/mem bs=4096 skip=... count=...` 读取目标模块映射，二进制数据经 `adb exec-out` 直接保存到电脑。

采集：Cocos 4 段、FairGuard 4 段，共 21,331,968 字节（约 20.34 MiB）。逐段记录起止地址、文件偏移、权限与 SHA-256；不扫描其他应用内存。

本次模块基址：

| 模块 | 基址 |
|---|---|
| libcocos2dlua.so | `0x7ba8c21000` |
| libFairGuard.so | `0x7bab6eb000` |

这些是本次 ASLR 地址，不应硬编码到后续设备会话。脚本从 maps 获取基址并校验目标 PID。

运行时字符串恢复了 `AppDelegate`、`ResourcesDecode`、`main.lua`、C++ mangled names、Lua 搜索路径等；相应位置可以反汇编。因此确实取得了原始 APK 中不可直接读出的代码／数据。

### 5. 构造分析映像：成功，但不是可运行脱壳 SO

最初按整个 maps 页覆盖原文件，会误覆盖文件尾部未映射的 ELF 节表，pyelftools 随后报 `String Table not found`／解析错误。修正为只合并原 `PT_LOAD.p_filesz` 与采集分段的交集，保留原始非映射元数据。

修正后主引擎约 15,822,957 个字节与磁盘版本不同，FairGuard 约 4,352,790 个字节不同。差异包含解密、清零、重定位及运行状态，**不是“还原了这么多字节的有效代码”**。

原节表仍被保护。为 LLVM 建立人工 `.text` 分析窗口 `[0x200000, 0xbf0000)`，并将异常壳侧符号节按普通数据处理，解决 `invalid section index: 61`。该窗口只用于已定位地址的反汇编，不表示真实代码边界。

限制：原始动态符号／部分元数据在运行后被清理；当前 GOT 有绝对进程地址；还存在匿名跳板。因此 `*.memory.so` / `*.analysis.so` 均不能替换 APK 中 SO，未验证重新加载或重打包运行。

### 6. 从 main.lua 追到资源对象：成功

在主引擎中从字符串交叉引用定位 AppDelegate 调用片段：

- `cocos+0x3c4b80` 附近为 LuaStack 默认 `2dxLua` / `XXTEA` 初始化。
- `cocos+0x3c4bc0` 附近先执行 bootstrap 路径，再执行 `main.lua`。
- `cocos+0x733898` 附近分割常量 `0db5c76bad3972ad8ad44aab87f92768` 的前后 16 字节，调用资源密钥设置函数。
- `cocos+0x73c75c` 获取 ResourcesDecode 单例；GOT 槽位 RVA `0xf13708` 指向单例全局变量。
- `cocos+0x73cd18` 为资源密钥设置函数；`0x73c808` 为签名检查；`0x73c9c8 / 0x73ca9c / 0x73cb70` 构成分层解码链。

上述函数角色来自指令、字段偏移和调用数据流，不是全部已由调试符号自动恢复出的名字。

读取对象时，首次失败原因是 Android ARM64 的 tagged heap pointer；屏蔽顶部标签字节后，按确认的 112 字节对象布局读取成功。

| 对象字段 | 观察到的 ASCII 值 | 角色 |
|---|---|---|
| `+0x00` | `f791a52aa9044ff8` | 一层派生 key |
| `+0x10` | `ec9336077f73f54c` | 与 APK 中 18,549 个文件头匹配的 sign |
| `+0x20` | `df4bfa8f86aa2c13` | 另一层派生 key |
| `+0x30` | `200fe21de56df0f8` | 另一层 sign |
| `+0x40` | `0db5c76bad3972ad` | 原始设置 key |
| `+0x50` | `8ad44aab87f92768` | 原始设置 sign |

这些是资源保护参数，不是账号或服务器凭据。证据为 `evidence/resource_state.json` 与相关汇编文件。

### 7. 标准 XXTEA 离线试解：未成功

对 8 个最小带签名资源，跳过前 16 字节，使用观察到的 5 个候选字段逐一尝试标准 XXTEA。没有候选通过末尾原始长度校验，`evidence/xxtea_probe.txt` 无成功项。

这不证明算法不可逆，也不能拿候选 key 宣称资源已解开。进一步检查确认存在前置保护：

```text
ResourcesDecode 分层解码
  -> cocos+0x4c3fc8（XXTEA wrapper 已有运行时跳转）
  -> 匿名页 0x7f03fe2000
  -> cocos+0xf739ec
       -> FairGuard+0x341660(buffer, length) 预处理
       -> 匿名页 0x7f03fe2014 保存的原始序言
       -> cocos+0x4c3fd8 -> 标准 XXTEA core cocos+0x4c3b60
```

该跳转在采集前已存在，并非本轮脚本写入。根据实际函数指针，其预处理地址 `0x7baba2c660` 位于 FairGuard 映射。前置函数中可见 4096 字节阈值与额外状态读取，但尚未完整还原其全部算法／覆盖长度，不能简化声称“只需 XOR”或“只处理前 4 KB”。

### 8. 整理交付：完成

保留原始分段、分析映像、对象状态、汇编、静态产物、错误记录和可复现脚本。另准备了在 **XXTEA core 返回处**采集解密输出的 Frida 脚本，避开前置保护造成的直接离线试解问题。该脚本未实际注入，不能当作已经拿到 Lua 明文的证据。

## 本轮边界

已完成的是：初步架构理解、native 壳证据、只读内存脱壳、具体资源链路与后续方案。

尚未完成的是：FairGuard 前置算法静态复现、加密资源解密、Lua 业务恢复、符号／重定位完整修复及可运行脱壳 APK。没有获取或还原服务端源码，没有修改设备上的游戏文件、游戏内存或支付／账号逻辑。
