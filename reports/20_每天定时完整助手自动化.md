# 每天定时完整助手自动化

日期：2026-10-14

## 目标

用 AutoJs6 每天北京时间 07:00 唤醒手机，启动《斗罗大陆：武魂觉醒》，关闭已识别的 SDK 广告和公告，进入已绑定角色，通过 LSPosed 扩展请求执行一次游戏内香香小助手的完整任务列表。AutoJs 只负责系统和页面入口，业务队列仍由游戏内 Lua 模块执行。

## 已实现

- `autojs/run-helper.js`：Root 唤醒、解锁、截图、模板匹配、启动游戏、等待角色和业务回执、成功后关闭游戏。
- `autojs/setup-schedule.js`：调用 AutoJs6 6.7.0 的 `tasks.addDailyTask` 注册每天 07:00 任务，并只替换同一脚本路径的旧任务。
- `modules/helper_automation.lua` 与 `modules/helper_automation_game.lua`：完整队列请求协议、角色/服务器/游戏日校验、持久去重、执行监视、回执和逐条结果。
- `lsposed-module` 版本 0.3.0：游戏启动后提供 `ready.tsv`，收到显式请求才打开原生一键助手窗口。

AutoJs 脚本和配置放在其私有目录 `/data/user/0/org.autojs.autojs6/files/dldl/`。Root 命令使用 KernelSU 的 `su -M -c`，因为普通 Root shell 仍在 AutoJs 的挂载命名空间，看不到游戏私有目录。当前手机已授权 AutoJs Root、精确闹钟、后台运行和电池优化豁免；未使用共享存储、MediaProjection 或无障碍服务。

## 实机证据

1. 通过游戏内助手执行完整列表：46 个条目，覆盖 16 个官方类别；32 个官方条目实际执行，14 个自定义条目因当天已完成/无剩余次数而跳过。回执为 `completed / queue_finished`，每一行均有终态。
2. 使用 AutoJs 从游戏登录页冷启动：成功识别并点击“APK更新以后再说”、活动公告关闭，进入主城；向模块发送 `daily-20739-5005`。
3. 模块返回 `already_completed / daily_run_completed`，证明当天重复请求被持久化保护，AutoJs 没有重复打开完整队列或重复消费道具；随后按配置关闭游戏。
4. 系统 `dumpsys alarm` 已确认持久精确 `RTC_WAKEUP`：2026-10-14 07:00、`window=0`、`exactAllowReason=policy_permission`，动作是 AutoJs6 的 `ACTION_RUN_ALARM_TIMED_TASK`。
5. 灰度主城模板在压暗空闲画面上的实测相似度为 0.99987；模板匹配固定使用原尺寸并限制区域。Root 命令有 20 秒超时，避免输出管道或系统命令导致脚本无期限卡住。

## 安全边界

脚本请求有效期 240 秒。模块按角色、服务器、游戏日（北京时间 05:00 刷新）校验；同一角色同一游戏日只接受一次自动请求。完成返回 `already_completed`，上次执行未确认返回 `uncertain`，不会自动重跑可能消费挑战券、契约或次数的完整列表。单项资源不足继续后续项目，逐条状态写入 `tasks.tsv`。不执行 APK 更新、不购买额外资源、不切换角色。

## 当前限制

已识别的广告、公告和登录按钮来自当前客户端模板。新版本变更文字、位置、分辨率或新增陌生弹窗时，脚本会停止并保留日志/截图，不会盲目点击。账号掉线、验证码、密码锁屏、网络异常需要人工处理。真实 07:00 后台闹钟已安装并由系统确认；本次在开发时段验证了冷启动和回执，未等待到下一个 07:00 观察整段无人值守流程，因此后续版本更新仍需重新核对模板和业务接口。

可查看：AutoJs 私有目录的 `last-run.log`、`last-tasks.tsv`、`screen.png`；这些文件可能包含角色信息，不要提交到仓库。安装、权限、回退和协议说明见 [autojs/README.md](../autojs/README.md)。

## 2026-10-17 启动卡住修复

用户截图停在可选 APK 更新提示。原 `update-later.png` 在该截图的既定区域内归一化相关系数约 0.990，超过匹配阈值 0.92；不需要放宽阈值或增加固定坐标点击。

手机日志显示 10月14日、16日、17日的定时启动在请求启动游戏后立即报“游戏未在前台”，启动切换尚未完成就退出。10月15日及本次首次诊断还出现长时间暂停。实机发现 AutoJs 侧栏“前台服务”关闭，进程进入缓存状态，新增的 partial wake lock 也被系统标记为 DISABLED；已有电池白名单不足以防止该情况。

修复与部署：

- 开启手机 AutoJs 的前台服务，确认系统服务记录 `isForeground=true`。
- 脚本增加前台服务自检、最长40分钟的 CPU 唤醒锁，退出释放；启动后最多等待45秒进入游戏前台，等待期间不点击，实际点击前再次核对前台。
- 增加 `verify-startup.js`，共用真实启动、角色和业务就绪检查，但不发送助手队列请求。
- 已部署到原 AutoJs 私有目录，旧脚本备份为 `run-helper.before-20261017.js`，保留角色配置及原每日07:00定时任务。
